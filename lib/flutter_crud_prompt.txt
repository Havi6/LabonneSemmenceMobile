Prompt pour une IA Flutter :

Objectif :
- Implémenter dans Flutter la même logique CRUD que l'application backend existante pour :
  1. Galerie (fichiers/images)
  2. Événements
  3. Contact
  4. Sermons

Contexte :
- Le backend expose des API REST avec des routes Express.
- Certaines routes sont publiques, d'autres nécessitent un token d'authentification admin.
- Les fichiers de la galerie sont gérés via un service de stockage (Supabase) et exposés par l'API.

Routes et comportement attendu :

1) Galerie
- GET /api/files/public?usage=gallery
  - Liste les fichiers publics de la galerie.
  - Paramètre facultatif : usage=gallery ou cover.
- POST /api/files/upload
  - Upload d'un fichier (image/ressource) en multipart/form-data.
  - Champs : file, is_public (true/false), legend, usage (gallery ou cover), categorie.
  - Requiert authentification.
- PATCH /api/files/:id/visibility
  - Met à jour la visibilité publique/privée du fichier.
  - Requiert authentification.
  - Body JSON : { "is_public": true }
- DELETE /api/files/:id
  - Supprime un fichier.
  - Requiert authentification.

Exemple de modèle Flutter pour la galerie :
- id
- filename
- original_name
- legend
- usage
- categorie
- mimetype
- size
- uploader_id
- is_public
- created_at

2) Événements
- GET /api/events
  - Récupère tous les événements.
- POST /api/events
  - Crée un événement.
  - Requiert authentification admin.
- PUT /api/events/:id
  - Met à jour un événement.
  - Requiert authentification admin.
- DELETE /api/events/:id
  - Supprime un événement.
  - Requiert authentification admin.

Corps attendu pour POST/PUT événements :
{
  "titre": "Titre de l evenement",
  "lieu": "Lieu",
  "description": "Description",
  "image_url": "https://...", // facultatif
  "categorie": "Categorie",
  "heure": "10:00",
  "date": "2024-05-20"
}

Modèle Flutter pour un événement :
- id
- titre
- lieu
- description
- image_url
- categorie
- heure
- date
- created_at
- updated_at

3) Contact
- POST /api/contacts
  - Envoie un message de contact.
  - Body JSON : { "nom", "email", "sujet", "contenu" }
  - Public.
- GET /api/contacts
  - Récupère tous les messages de contact.
  - Requiert authentification admin.
- DELETE /api/contacts/:id
  - Supprime un message de contact.
  - Requiert authentification admin.

Modèle Flutter pour message de contact :
- id
- nom
- email
- sujet
- contenu
- created_at

4) Sermons
- GET /api/sermons
  - Récupère tous les sermons.
- POST /api/sermons
  - Crée un sermon.
  - Requiert authentification admin.
- PUT /api/sermons/:id
  - Met à jour un sermon.
  - Requiert authentification admin.
- DELETE /api/sermons/:id
  - Supprime un sermon.
  - Requiert authentification admin.

  "categorie": "Dimanche"
}

Autres consignes :
- Utiliser des appels HTTP avec gestion des erreurs.
- Ajouter l'en-tête Authorization: Bearer <token> pour les routes admin.
- Prévoir des services/repositories Flutter séparés pour chaque entité.
- Pour la galerie, gérer l'upload multipart/form-data et le streaming ou téléchargement de fichiers.
- Pour l'UI Flutter, prévoir des écrans de liste, de création/édition, et de détail quand nécessaire.
- Respecter les règles de validation du backend : champs requis, email valide pour le contact.

Tâches à réaliser :
- Créer les modèles Dart pour Events, Sermons, ContactMessage et GalleryFile.
- Créer un service HTTP Flutter pour appeler les endpoints correspondants.
- Implémenter les opérations CRUD dans Flutter pour chaque entité.
- Si nécessaire, ajouter un gestionnaire d'authentification pour récupérer et stocker le token.
